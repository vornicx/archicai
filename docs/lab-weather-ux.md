# Archic Lab Weather — UX/data integrity notes (third pass, 2026-11)

- **Forecast ownership** (`src/lab/forecastState.ts`, tests `tests/lab-forecast-state.test.mjs`): every payload is stored with the key of the place it was requested for (`lat,lon` to 3 decimals) and a request id. Only the latest request may write; superseded or late responses (including failures) are dropped. A new place shows a labelled skeleton with its own name until its data arrives — never the previous place's numbers. Refreshing the same place keeps its data, dimmed, with a visible "Actualizando…" status. A failed request hides data and offers "Reintentar".
- **Hour selection** (`src/lab/hourSelection.ts`, tests `tests/lab-rain-selection.test.mjs`): the hourly strip is a row of 72 px buttons (`aria-pressed`, `time dateTime`, roving tabindex, arrows/Home/End). The selected hour highlights its bar in `RainBars` via `selectedIndex` and shows a compact real-data line under the chart ("21:00 · 0,0 mm · 19 °C · …"; missing values read "—"). Bars stay a single `role="img"`, with no interactive targets, so the compact chart can live inside the Lab link.
- **Wording**: the Lab preview says "Predicción de modelo / Model forecast" with "MET Norway · actualizado HH:MM"; no "live/en vivo".
- **Strip scrolling**: thin visible scrollbar, edge fade removed while focused, snap at start of each hour, reduced-motion disables press scale and smooth scroll.
- **QA limit**: local browser checks route the Edge Function to fixtures because the function correctly refuses the localhost origin; the real Lovable preview was not exercised end to end.
